# AI-Fund Idea Intake Protocol

## Purpose

This document defines how Itera Dynamics should consume ideas generated by the separate AI-fund project.

The AI-fund project can generate plausible trade ideas across macro, equities, sectors, long/short, and other research lanes. These ideas are useful as research prompts, but they must not be treated as Itera trade instructions.

The goal is to convert agent-generated trade ideas into structured Itera research candidates.

---

## Core Rule

```text
AI-fund outputs are not trades.
AI-fund outputs are research idea inputs.
```

Every AI-fund idea must pass through Itera triage before it can affect the research radar or ID_test validation queue.

---

## Intake Pipeline

```text
AI-fund idea
  -> freshness / source sanity check
  -> portfolio-role classification
  -> deterministic translation
  -> research-radar triage
  -> ID_test validation task if accepted
```

No AI-fund idea may directly modify:

```text
runtime code
live governors
broker execution
portfolio allocation
production state
```

---

## Triage Statuses

Each idea receives one status:

```text
REJECT
ARCHIVE
TRANSLATE
QUEUE
ACTIVE TEST
```

### REJECT

Use when the idea is not useful for Itera.

Examples:

- pure discretionary stock call
- no deterministic test possible
- unsupported rationale
- not tradeable in Itera's intended universe
- violates risk constraints

### ARCHIVE

Use when the idea is stale, duplicate, or already covered.

Examples:

- old macro data used as current rationale
- duplicate of an existing research lane
- idea already tested and rejected

### TRANSLATE

Use when the idea is directionally interesting but must be converted into an Itera-compatible research candidate.

Examples:

- single-name equity idea becomes an ETF/sector/factor research candidate
- discretionary macro trade becomes a deterministic cross-asset filter
- trade recommendation becomes a destination-matrix hypothesis

### QUEUE

Use when the translated idea is added to the research radar backlog.

### ACTIVE TEST

Use only when the idea has been selected for deterministic ID_test research.

## Freshness Gate

AI-fund outputs must be checked for stale or mismatched data.

Macro and market claims must include or imply a valid as-of date.

Downgrade or archive ideas when:

```text
old macro data is presented as current
market levels are stale
rationale depends on outdated CPI / GDP / Fed pricing
source date is unclear
current market context contradicts the premise
```

Freshness failures do not always make the idea useless. They may still reveal a research lane, but they should not be accepted as current market views.

---

## Portfolio-Role Gate

Each idea must be assigned a role before it enters Itera research.

Common roles:

```text
return engine
defensive destination
risk-off confirmation
risk-on enhancer
portfolio diversifier
volatility smoother
capital parking
regime filter
execution / cost improvement
```

If no portfolio role can be assigned, the idea should be rejected or archived.

---

## Deterministic Translation Gate

Every useful idea must be reducible to a deterministic test.

Bad Itera form:

```text
Long TLT because the Fed may cut soon.
```

Good Itera form:

```text
Test TLT or IEF as a risk-off destination only when duration trend is positive.
Example rule: TLT close > TLT SMA200 during state-confirmed crypto risk-off.
Benchmark against GLD/BIL, BIL-only, and cash.
```

Bad Itera form:

```text
Long ASML because valuation upside exists.
```

Good Itera form:

```text
Test AI infrastructure / semiconductor ETF exposure as a risk-on destination.
Candidate ETFs: SMH, SOXX, XLK, IGV, QQQ.
Only evaluate during crypto-friendly regimes.
```

## Guardrail Questions

Before an idea enters the queue, answer:

```text
Can this be tested without lookahead?
Does it have a clear baseline?
Does it solve a portfolio problem?
Is the instrument universe tradeable or at least researchable?
Does the idea duplicate an existing candidate?
Is the rationale fresh enough to be useful?
What would falsify the idea?
```

## Example Intake: TLT Macro Long

Original form:

```text
LONG TLT because long yields may fall and the Fed may ease.
```

Itera translation:

```text
Duration-filtered bond destination.
```

Research lane:

```text
Macro / Cross-Asset
```

Portfolio role:

```text
Defensive destination / duration-sensitive diversifier
```

Deterministic test:

```text
During state-confirmed crypto risk-off, allocate to TLT or IEF only when duration trend is favorable.
Possible filter: TLT close > TLT SMA200.
Benchmark against GLD/BIL, GLD-only, BIL-only, and cash.
```

Triage status:

```text
TRANSLATE -> QUEUE
```

## Boundary

The AI-fund idea intake is useful because it expands research coverage.

It is not allowed to become an execution source.

Final rule:

```text
AI-fund proposes.
Itera triages.
ID_test validates.
Human decides.
Runtime remains deterministic.
```
